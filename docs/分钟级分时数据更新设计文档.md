## 分钟级分时数据更新 — 设计开发文档

### 一、背景与目标

当前系统通过 Tushare 接口在"更新全部股票"时拉取各股票的**日线数据**，存储在 `stock_daily_data/` 目录下。

现在希望在更新全部股票时，**额外新增一个阶段**：利用同花顺公开的分时数据接口，批量获取各股票**最近一个交易日的分钟级分时数据**，为后续盘后分析（如分时量价分析、资金流向推算等）提供数据基础。

### 二、数据源分析

#### 2.1 接口信息

| 项目 | 说明 |
|------|------|
| **URL 模式** | `https://d.10jqka.com.cn/v6/time/hs_{6位股票代码}/defer/last.js` |
| **请求方式** | GET |
| **返回格式** | JSONP，需剥离回调函数名后解析 JSON |
| **必要请求头** | `User-Agent`（浏览器 UA）、`Referer: https://stockpage.10jqka.com.cn/` |
| **数据范围** | 仅最近一个交易日，共 242 个分钟数据点（9:30-11:30 + 13:00-15:00） |

#### 2.2 返回数据结构

```json
{
  "hs_002008": {
    "name": "大族激光",
    "pre": "112.41",
    "date": "20260508",
    "data": "0930,115.40,62015960,115.400,537400;0931,...",
    "dotsCount": 242,
    "marketType": "HS_stock_sz"
  }
}
```

**`data` 字段**每条记录用 `;` 分隔，每条内部用 `,` 分隔，共 5 个字段：

| 序号 | 字段 | 示例 | 含义 |
|------|------|------|------|
| 1 | time | `0930` | 分钟时间（HHmm） |
| 2 | price | `115.40` | 该分钟收盘价 |
| 3 | amount | `62015960` | 该分钟成交额（元） |
| 4 | avg_price | `115.400` | 当日累计均价 |
| 5 | volume | `537400` | 该分钟成交量（股） |

#### 2.3 可行性验证结论

- 沪市主板(60xxxx)、深市主板(00xxxx)、创业板(30xxxx)、科创板(68xxxx) 均可正常返回
- 20 只股票并发请求全部 200，耗时仅 0.38s，无限流
- 需要 `User-Agent` + `Referer` 请求头

### 三、整体设计方案

#### 3.1 在更新流程中的位置

现有 `update_all_symbols()` 流程：

```
阶段1: 逐只更新个股日线 (update_symbol)
阶段2: 更新指数日线 (update_index)
--- 新增 ---
阶段3: 批量获取分钟级分时数据 (update_minute_data)
```

在**日线数据全部更新完成后**，新增阶段 3 执行分时数据拉取，与日线更新共享同一个进度弹窗。

#### 3.2 数据存储方案

```
trader/
├── stock_daily_data/        # 现有日线数据（不变）
│   ├── 000001.csv
│   └── ...
├── stock_minute_data/       # 新增：分钟级分时数据
│   ├── 000001.csv
│   ├── 002008.csv
│   └── ...
```

每只股票对应一个 CSV 文件，**仅保存最近一个交易日的数据**（每次更新覆盖写入）。

CSV 列定义：

| 列名 | 类型 | 说明 |
|------|------|------|
| `date` | str | 交易日期，格式 `YYYY-MM-DD` |
| `time` | str | 分钟时间，格式 `HH:MM` |
| `price` | float | 该分钟收盘价 |
| `amount` | float | 该分钟成交额（元） |
| `avg_price` | float | 当日累计均价 |
| `volume` | int | 该分钟成交量（股） |
| `pre_close` | float | 前收盘价（冗余存储，方便计算涨跌幅） |

示例数据：

```csv
date,time,price,amount,avg_price,volume,pre_close
2026-05-08,09:30,115.40,62015960,115.400,537400,112.41
2026-05-08,09:31,115.69,374634470,114.949,3261257,112.41
```

#### 3.3 核心模块划分

| **THS 分时数据客户端** | `app/ths_minute_client.py`（新建） | 封装同花顺接口请求、JSONP 解析、数据转 DataFrame |
| **HistoryUpdater 扩展** | `app/history_updater.py`（修改） | 在 `update_all_symbols` 末尾新增阶段 3 调用 |

### 四、详细设计

#### 4.1 `app/ths_minute_client.py` — 同花顺分时数据客户端

```python
class ThsMinuteClient:
    """同花顺分时数据客户端"""

    BASE_URL = "https://d.10jqka.com.cn/v6/time/hs_{symbol}/defer/last.js"
    HEADERS = {
        "User-Agent": "Mozilla/5.0 ...",
        "Referer": "https://stockpage.10jqka.com.cn/",
    }

    def fetch_minute_data(self, symbol: str) -> pd.DataFrame | None:
        """获取单只股票最近交易日的分钟数据，返回 DataFrame"""

    def fetch_batch(
        self,
        symbols: list[str],
        max_concurrent: int = 5,
        delay_seconds: float = 0.2,
        progress_callback=None,
        stop_checker=None,
    ) -> dict[str, pd.DataFrame]:
        """批量获取多只股票的分时数据"""
```

**关键实现要点**：

1. **JSONP 解析**：用正则 `re.search(r'\((\{.*\})\)', text)` 剥离回调函数名
2. **data 字段解析**：按 `;` 拆分为条目，再按 `,` 拆分为字段
3. **日期格式化**：`"20260508"` → `"2026-05-08"`，`"0930"` → `"09:30"`
4. **错误处理**：单只股票请求失败不影响其余股票，记录错误日志
5. **并发控制**：使用 `concurrent.futures.ThreadPoolExecutor`，控制并发数（默认 5）
6. **请求间隔**：批次之间加 0.2s 随机延迟，避免触发反爬

#### 4.2 `app/history_updater.py` — 更新流程扩展

在 `update_all_symbols()` 方法末尾，日线 + 指数更新完成后，新增阶段 3：

```python
# === 阶段3: 更新分钟级分时数据 ===
if not cancelled:
    minute_results = self._update_all_minute_data(
        symbols, progress_callback, stop_checker,
        current_offset=len(symbols) + len(self.INDEX_CODES),
        total=new_total,
    )
```

新增方法 `_update_all_minute_data()`：

- 实例化 `ThsMinuteClient`
- 调用 `fetch_batch()` 批量拉取
- 每只股票拉取成功后，写入 `stock_minute_data/{symbol}.csv`
- 通过 `progress_callback` 报告进度（stage 标识为 `"minute_updating"`）

**进度条集成**：

- total 数量调整为 `个股数 + 指数数 + 个股数(分时)`
- 新增 stage_text: `"正在获取分钟级分时数据"`

### 五、请求策略与风控

| 策略项 | 设计值 | 说明 |
|--------|--------|------|
| **并发数** | 5 | ThreadPoolExecutor 最大并发 |
| **批次间延迟** | 0.1-0.3s 随机 | 每个请求完成后随机延迟 |
| **超时时间** | 5s/请求 | 单个请求超时 |
| **重试次数** | 1 次 | 失败后重试 1 次，再失败则跳过 |
| **跳过逻辑** | 本地已是当天数据则跳过 | 避免重复拉取 |

以 ~3000 只股票为例，预估耗时：

- 并发 5，每只平均 0.3s（含延迟）→ `3000 / 5 * 0.3 ≈ 180s ≈ 3 分钟`
