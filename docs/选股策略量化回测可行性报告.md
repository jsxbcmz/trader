**历史状态回溯 — 细则说明**

回测过程中需要逐日记录完整的状态快照，用于事后分析和指标计算：

| 记录项 | 说明 |
|---|---|
| **日期** | 当前交易日 |
| **总资产** | 可用资金 + 所有持仓市值 |
| **可用资金** | 当日剩余现金 |
| **持仓明细** | 每只股票的代码、数量、成本价、当日收盘价、浮动盈亏 |
| **当日交易** | 当日发生的买入/卖出记录 |
| **当日收益率** | `(今日总资产 / 昨日总资产) - 1` |
| **累计收益率** | `(今日总资产 / 初始资金) - 1` |

每日快照存储为列表，回测结束后可用于：
- 绘制**资金曲线**（equity curve）
- 计算**最大回撤**（需要逐日峰值追踪）
- 生成**月度/年度收益分布**
- 回放任意时间点的持仓状态

**性能指标统计 — 细则说明**

| 指标 | 公式 / 说明 | 用途 |
|---|---|---|
| **总收益率** | `(期末总资产 / 初始资金) - 1` | 衡量策略整体盈利能力 |
| **年化收益率** | `(1 + 总收益率) ^ (252 / 交易天数) - 1` | 标准化为年度收益，便于跨策略对比 |
| **最大回撤** | `max(1 - 谷值 / 前期峰值)`，遍历每日总资产计算 | 衡量策略最坏情况下的亏损幅度 |
| **夏普比率** | `(年化收益率 - 无风险利率) / 年化波动率`，无风险利率取 3% | 风险调整后收益，>1 为良好，>2 为优秀 |
| **胜率** | `盈利交易次数 / 总交易次数` | 赢面大小 |
| **盈亏比** | `平均盈利金额 / 平均亏损金额` | 赚的多还是亏的多 |
| **交易次数** | 总买卖笔数 | 策略活跃度 |
| **平均持仓天数** | `所有交易持有天数之和 / 交易笔数` | 策略持仓周期 |
| **最大连续亏损** | 连续亏损交易的最大次数 | 心理承受压力评估 |
| **收益波动率** | 每日收益率的标准差 × √252（年化） | 策略稳定性 |
| **Calmar 比率** | `年化收益率 / 最大回撤` | 收益与风险的综合评价，>3 为优秀 |

#### 3.3 回测执行逻辑（伪代码）

```python
def run_backtest(config: BacktestConfig):
    portfolio = Portfolio(config.initial_capital)
    trades = []

    for trade_date in get_trading_days(config.start_date, config.end_date):
        # 1. 更新持仓价格，检查止损/止盈/到期
        for holding in portfolio.holdings:
            current_price = get_close_price(holding.symbol, trade_date)
            holding.update_price(current_price)

            if should_sell(holding, config, trade_date):
                sell_order = portfolio.sell(holding, current_price, trade_date)
                trades.append(sell_order)

        # 2. 运行选股引擎，生成买入信号
        screening_result = screening_engine.screen(
            tdx_source=config.tdx_source,
            target_date=trade_date,
            stock_pool=config.stock_pool_name
        )

        # 3. 执行买入（按可用资金和仓位限制）
        for match in screening_result.matches:
            if portfolio.can_buy(config):
                buy_price = get_close_price(match.symbol, trade_date)
                buy_order = portfolio.buy(match.symbol, buy_price, trade_date, config)
                trades.append(buy_order)

    # 4. 计算绩效指标
    metrics = calculate_metrics(portfolio, trades, config)
    return BacktestReport(trades, metrics, portfolio)
```

#### 3.4 绩效指标

| 指标 | 说明 | 计算方式 |
|---|---|---|
| **总收益率** | 期末资产/初始资金 - 1 | `(final_value / initial_capital) - 1` |
| **年化收益率** | 按交易天数折算 | `(1 + total_return) ^ (252/days) - 1` |
| **最大回撤** | 峰值到谷值的最大跌幅 | `max(1 - valley/peak)` |
| **夏普比率** | 风险调整后收益 | `(annual_return - rf) / annual_std` |
| **胜率** | 盈利交易占比 | `win_trades / total_trades` |
| **盈亏比** | 平均盈利/平均亏损 | `avg_profit / avg_loss` |
| **交易次数** | 总买卖次数 | 直接统计 |
| **平均持仓天数** | 每笔交易持有时间 | `sum(hold_days) / trades` |
| **最大连续亏损** | 连续亏损的最大次数 | 遍历统计 |

### 四、以"砖形图策略"为例的回测方案

#### 4.1 策略概述

当前项目中用户自定义的**砖形图策略**是最复杂、最有回测价值的策略：

**买入信号**（7个条件同时满足）：

1. **绿转红**：砖型图指标从绿柱转为红柱
2. **有效红柱**：当日砖型图值 > 0
3. **有效绿柱**：前一天绿柱高度 > 0
4. **长度条件**：红柱高度 ≥ 前绿柱高度的 70%
5. **股价区间**：连续两天收盘价站上多空线，且低于短趋线 × 1.02
6. **趋势条件**：短趋线 > 多空线

#### 4.2 买入策略设计（砖形图专属）

当选股引擎在某个交易日触发买入信号后，按以下规则执行买入：

| 维度 | 规则 | 说明 |
|---|---|---|
| **买入时机** | 可配置，支持两种模式：① 信号触发日的**当天收盘价**买入；② 信号触发日的**次日开盘价**买入 | 模式①假设盘中即可识别信号并在尾盘买入；模式②更贴近实盘（T+1 开盘执行）。两种模式可对比分析不同买入时机对收益率的影响 |
| **买入数量** | 按仓位比例计算，向下取整到 100 股（1手） | `买入股数 = floor(可用资金 × 仓位比例 / 买入价 / 100) × 100` |
| **仓位分配** | 单只股票仓位比例可手动配置（如 10%） | 初始资金 100 万 × 10% = 单只最多投入 10 万 |
| **最大持仓数** | 可手动配置（如 10 只） | 超过上限时，新信号不再买入 |
| **重复信号** | 已持仓的股票不重复买入 | 避免同一只股票叠加仓位 |
| **资金不足** | 可用资金不足以买入 1 手时跳过 | 等待卖出释放资金后再买入 |

**买入策略伪代码**：

```python
def execute_buy(signal, portfolio, config):
    # 根据配置选择买入价格
    if config.buy_timing == "CLOSE":
        # 模式①：信号触发日当天收盘价买入
        buy_price = get_close_price(signal.symbol, signal.date)
    else:
        # 模式②：信号触发日次日开盘价买入（默认）
        buy_price = get_open_price(signal.symbol, next_trading_day(signal.date))

    # 已持仓不重复买入
    if portfolio.has_holding(signal.symbol):
        return None

    # 持仓数量上限检查
    if portfolio.holding_count >= config.max_positions:
        return None

    # 计算买入数量（向下取整到100股）
    available_amount = portfolio.cash * config.position_size
    shares = int(available_amount / buy_price / 100) * 100

    # 资金不足
    if shares < 100:
        return None

    # 扣除佣金
    cost = shares * buy_price
    commission = max(cost * config.commission_rate, config.min_commission)

    return portfolio.buy(signal.symbol, buy_price, shares, cost + commission)
```

#### 4.3 卖出策略设计（砖形图专属）

砖形图策略的止损/止盈规则与砖型图指标深度绑定，属于**策略级动态配置**：

**止损规则**（满足任一即触发）：

| 条件 | 说明 |
|---|---|
| **绿砖止损** | 买入后次日起，出现绿砖（砖型图值下降）立即清仓 |
| **破成本止损** | 收盘价跌破买入成本价，立即清仓 |

**止盈规则**（分批止盈 + 信号清仓）：

| 阶段 | 条件 | 操作 |
|---|---|---|
| **持有期** | 持续红砖（砖型图值上升） | 继续持有，不操作 |
| **分批止盈** | 持有期间累计涨幅 ≥ 4~5% | 卖出 1/4 仓位，锁定利润垫 |
| **信号清仓** | 红砖首次转绿（砖型图值由升转降） | 清仓剩余全部仓位 |

**卖出策略伪代码**：

```python
@dataclass
class BrickChartSellStrategy(SellStrategy):
    partial_profit_threshold: float = 0.045  # 分批止盈阈值（4.5%）
    partial_sell_ratio: float = 0.25         # 分批卖出比例（1/4）

    def should_sell(self, holding, current_bar, prev_bar):
        brick_value = calc_brick(current_bar)
        prev_brick_value = calc_brick(prev_bar)

        # 止损：出现绿砖
        if brick_value < prev_brick_value:
            return SellSignal(action="CLEAR", reason="绿砖止损")

        # 止损：跌破成本价
        if current_bar.close < holding.cost_price:
            return SellSignal(action="CLEAR", reason="破成本止损")

        # 分批止盈：涨幅达标且未做过分批
        profit_rate = (current_bar.close - holding.cost_price) / holding.cost_price
        if profit_rate >= self.partial_profit_threshold and not holding.partial_sold:
            return SellSignal(action="PARTIAL", ratio=self.partial_sell_ratio, reason="分批止盈")

        # 继续持有
        return SellSignal(action="HOLD")
```

|---|---|---|
| **数据量大** | 全 A 股 × 2年 ≈ 5000只 × 500天，选股引擎需逐日执行 | 利用现有多进程并行 + 缓存机制；可先用小股票池验证 |
| **选股性能** | 每个交易日都要跑一次全量选股，耗时较长 | 分批执行 + 进度展示；可预计算信号表 |
| **数据缺失** | 部分股票可能缺少某些日期的数据 | 复用现有的 `error_policy` 错误处理机制 |
| **未来函数** | 选股条件可能无意中使用了未来数据 | 严格使用 `target_date` 截断数据 |
| **幸存者偏差** | 退市股票不在当前股票列表中 | 当前阶段可接受，后续可引入历史成分股 |
| **交易日历** | 缺少完整的 A 股交易日历 | 可从数据中提取实际交易日（取任一大盘股的日期序列） |

#### 6.1 入口位置

当前主窗口有 4 个 Tab 页面：**看盘页（0）、模板页（1）、设置页（2）、选股页（3）**。

### 七、结论

| 评估维度 | 结论 |
|---|---|
| **技术可行性** | ✅ **完全可行** — 数据、选股引擎、交易模拟器三大基础设施齐备 |
| **数据可行性** | ✅ **完全满足** — 日线 OHLCV + 换手率覆盖技术分析需求 |

**建议**：先以**砖形图策略 + 小股票池（如沪深300成分股）+ 近1年数据**快速验证 MVP，再逐步扩展到全 A 股和更长时间范围。

#### 8.4 核心架构设计

**回测引擎数据流**：

```
BacktestConfig（配置）
    ↓
BacktestEngine.run()
    ├── _extract_trading_days()     → 交易日历（从大盘股日线数据提取）
    ├── 逐交易日步进 ──────────────────────────────────────
    │   ├── 步骤 0：执行前日待买入信号（次日开盘价模式）
    │   ├── 步骤 1：更新持仓价格 → SellStrategy.should_sell()
    │   │   ├── CLEAR  → _execute_sell() 全仓清仓
    │   │   ├── PARTIAL → _execute_sell() 部分卖出
    │   │   └── HOLD   → 继续持有
    │   ├── 步骤 2：ScreeningEngine.run() → 生成买入信号
    │   ├── 步骤 3：_execute_buy() → 仓位计算 + 资金扣款
    │   └── 步骤 4：记录 DailySnapshot
    │
    ↓
BacktestResult（结果）
    ↓
calculate_metrics()  → BacktestMetrics（11 项绩效指标）
    ↓
generate_markdown_report() / export_trades_csv()
```

**卖出策略扩展机制**：

```
SellStrategy（抽象基类）
    ├── DefaultSellStrategy     → 跌破成本 5% 止损
    └── BrickChartSellStrategy  → 绿砖止损 / 破成本止损 / 分批止盈 / 红转绿清仓

SELL_STRATEGY_REGISTRY = {"default": ..., "brick_chart": ...}
create_sell_strategy(name, params) → 工厂函数
```

**GUI 页面架构**：

```
MainWindow
    └── QStackedWidget
        ├── index 0: MarketPage（看盘页）
        ├── index 1: TemplatePage（模板页）──「回测」按钮──→ backtestRequested 信号
        ├── index 2: SettingsPage（设置页）
        ├── index 3: ScreeningPage（选股页）
        └── index 4: BacktestPage（回测页）← 新增
                      ├── 配置态：QScrollArea + QFormLayout 表单
                      └── 结果态：三栏布局
                          ├── 左栏：绩效概览（QTableWidget）
                          ├── 中栏：资金曲线（pyqtgraph）+ 月度收益表格
                          └── 右栏：交易明细（QTableWidget）
```
