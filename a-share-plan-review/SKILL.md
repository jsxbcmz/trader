# A股 Plan + Review Skill

将两类任务合并处理：
1. 盘前计划
2. 单笔交易复盘

目标不是复述 prompt，而是自动补齐尽可能多的有用上下文，再输出稳定结构。

这个 skill 默认面向股市小白：
- 先说人话结论，再给数据依据。
- 避免把输出写成研究报告，重点是“今天该看什么、别碰什么、为什么”。
- 术语第一次出现时，必须用一句白话解释。
- 用户没有完整数据时，先用最少输入完成，不因为缺少细节就卡住。
- 盘前模式默认偏保守，优先给“关注 / 等待 / 回避”，不鼓励追高。

---

## Step 1 — 识别模式

如果用户明确说的是以下任一意图，直接进入对应模式：
- 盘前计划 / 盘前执行表 / 看今天做什么 / 自选股筛选
- 交易复盘 / 纪律复盘 / 这笔交易哪里错了 / 进出场检查

如果用户没有说清楚，第一条回复只输出：

```text
你要做哪一种？

A) 盘前计划   — 自动收集消息、竞价、板块、关键位，输出今日执行表。
B) 交易复盘   — 自动收集盘面背景、板块联动、资金配合，输出纪律复盘。

请回复 A 或 B。
```

如果用户明确表示自己是新手，后续输出自动切换为“小白模式”：
- 每次最多重点展开 3 只股票。
- 尽量不用缩写。
- 每个结论后补一句“这对你意味着什么”。
- 如果信号不清楚，优先建议等待，不强行给进场结论。

---

## Step 2 — 加载规则

无论 A / B，都先读取：
1. `rules/data-collection.md`

然后按模式读取模板：
- A → `templates/pre-market.md`
- B → `templates/review.md`

读取后先做一件事：把模板中的专业字段翻译成用户能直接执行的语言。

例如：
- “板块联动” = 你买的票是不是跟着整个板块一起走强。
- “关键支撑” = 跌到这里再破位，说明判断大概率错了。
- “北向资金” = 外资当天总体是偏买还是偏卖，只能当辅助，不能单独下结论。

---

## Step 3 — 自动收集数据

### A 模式：盘前计划

优先使用用户已提供的数据；缺失部分再自动补采。最低需要覆盖：
1. 自选股列表
2. 隔夜消息 / 公告 / 催化剂
3. 集合竞价或前收信息
4. 所属板块与板块联动
5. 关键阻力 / 支撑 / 前高前低
6. 赚钱效应与市场风格

小白模式附加规则：
- 如果用户给了很多票，只保留最值得看的 3 只，其他放入“次级观察”。
- 如果没有集合竞价数据，可以退回前收、昨高低点和近 3-5 日趋势，不强行写竞价判断。
- 如果没有明确催化剂或板块共振，不要给“强关注”，最多写“普通观察”。
- 如果个股接近涨停、明显高开过多、或风险信息不清楚，优先给“回避 / 等待确认”。
- 所有操作建议必须包含“失效条件”，让新手知道什么情况下不做。

### B 模式：交易复盘

优先使用用户截图和交易描述；缺失部分再自动补采。最低需要覆盖：
1. 标的与交易日期
2. 进场 / 出场 / 计划止损 / 计划规则
3. 当日板块强弱与联动
4. 同时段指数环境与市场风格
5. 资金配合（北向 / 成交额 / 板块资金，能取到则取）
6. 当时是否存在情绪化背景（连亏、追涨、主观提前卖出）

小白模式附加规则：
- 先判断这笔交易属于哪一类：规则内亏损 / 冲动交易 / 追高接盘 / 提前卖出 / 侥幸扛单。
- 优先指出“最大的一个错误”，不要一次讲太多。
- 如果用户没有完整计划，只能依据已知信息做“弱结论”，明确哪些地方无法定责。
- 复盘重点是教会用户下次怎么做，不是堆砌市场背景。

如果外部数据无法取得：
- 明确列出“自动采集失败项”
- 不得编造
- 继续基于已知信息给出结果

## Step 4 — 输出要求

### A 模式输出

必须包含：
1. 一屏摘要
2. 今日盘前执行表
3. 赚钱效应 / 风格 / 最值得盯盘的 3 只票
4. **个股盘前操作建议**（每只自选股：操作倾向、进场条件、止损参考、风险提示）
5. 数据可得性与缺口

其中“一屏摘要”必须用下面这种顺序：
1. 今天适合做什么
2. 今天不适合做什么
3. 最该看的 3 只票
4. 如果你只看 10 分钟盘，先看什么

“个股盘前操作建议”必须写成白话，不允许只写技术词。每只票至少要回答：
- 该不该碰
- 什么时候才考虑进
- 什么情况下直接放弃
- 万一看错，哪里算错

### B 模式输出

必须包含：
1. 事实依据
2. 规则检查
3. 违规点
4. 心理模式
5. 可量化改进动作
6. 数据可得性与缺口

其中复盘第一段必须先给结论，格式固定为：
- 这笔交易的定性：
- 最大问题：
- 如果只改一个动作，下次先改：

复盘写法要求：
- 优先判断“是不是犯规”，再判断“是不是市场问题”。
- 用“你当时做对了 / 做错了什么”来写，不写空泛鸡汤。
- 不给买卖建议，只给纪律和流程改进建议。

## Step 5 — 保存报告

在输出报告给用户之后，**必须**将完整报告内容保存到文件。

### 文件命名规则

| 模式 | 路径 |
| ---- | ---- |
| A 盘前计划 | `reports/YYYY-MM-DD_盘前计划.md` |
| B 交易复盘 | `reports/YYYY-MM-DD_复盘_<标的代码>.md` |

- `YYYY-MM-DD` 为报告所对应的交易日期（盘前计划取**计划对应的交易日**，复盘取**交易当日**日期）。
- 若同日同类型文件已存在，自动追加数字后缀（`_2`、`_3` …）。
- 使用 `create_file` 工具写入，路径相对于工作区根目录 `c:\workspace\doc\AI\stock`。

### 保存内容

保存内容 = 对话中输出给用户的完整 Markdown 报告（一屏摘要 + 执行表 + 个股建议 + 数据可得性），**不包含**免责声明以外的额外解释。

### 保存后反馈

保存成功后，在回复末尾追加一行：

```
> 报告已保存至 reports/YYYY-MM-DD_盘前计划.md
```

---

## Step 6 — 通用约束

- 先结论，后展开。
- 优先短表格和短句，不写长段背景。
- 不编造新闻、竞价、板块、资金或技术面数据。
- 缺数据时先说明缺口，再输出当前最优结论。
- B 模式（复盘）：只做客观复盘，不给买卖建议。
- A 模式（盘前）：**必须**基于采集数据给出每只自选股的操作建议，包括：关注/回避/进场条件/止损参考。建议需依据数据，不得凭空给出。
- 默认使用“小白友好”语言。除非用户明确要求专业版，否则不要堆专业术语。
- 发现信号不充分时，允许明确给出“今天不做”或“先观察”，这也是有效结论。
- 不以预测涨跌为目标，而以帮助用户减少低质量交易为目标。
- 如果用户明显没有建立交易规则，复盘时要先帮他把本次隐含规则写出来，再判断是否违背。
