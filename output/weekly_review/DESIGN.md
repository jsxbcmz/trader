# 周度回顾系统 — 设计规范文档

> 本文档规定了周度回顾报告（`YYYY-WXX.md`）和持续迭代日志（`EVOLUTION.md`）的生成逻辑、格式规范和数据处理规则。
> 所有生成操作必须严格遵循本文档，确保跨周一致性。

---

## 一、系统背景

### 1.1 砖形图战法核心概念

- **红砖/绿砖定义**：当日砖值 - 前日砖值 > 0 为红砖（🔴），< 0 为绿砖（🟢）
- **交易纪律**：红砖持有、绿砖出局（红转绿即清仓），以 4 天为一个观察周期
- **三种交易定式**：N型起跳、横盘起跳、上升波段延续
- **核心胜率指标**：T+1 红砖保持率（选股次日是否继续保持红砖）

### 1.2 评分系统结构（V4）

```
总分 = Q(30分) + M(25分) + S(15分) + P(浮动加分) - R(浮动扣分)
```

| 模块 | 满分 | 说明 |
|------|------|------|
| Q - 信号质量 | 30 | K线形态、量价关系、缺口等 |
| M - MACD环境 | 25 | MACD方向、金叉/死叉、柱状图 |
| S - 信号强度 | 15 | 涨停封单、换手率、板块联动 |
| P - 额外加分 | 浮动 | 板块共振、连板晋级等 |
| R - 风险扣分 | 浮动 | 三波追高(-3)、短期过热(-5/-2)、冲高回落(-10)等 |

评分等级：S级(≥70) > A级(60-69) > B级(50-59) > C级(<50)

### 1.3 数据来源

| 数据源 | 路径 | 校验要求 |
|--------|------|----------|
| 原始扫描结果 | `output/screening_raw/{date}.json` | 必须齐全 |
| 自动预测 | `output/screening_predictions/{date}.json` | 必须齐全 |
| 手动预测 | `output/manual_predictions/{date}.json` | 允许部分缺失 |
| 分析报告 | `output/screening_analysis/{date}.md` | 允许部分缺失 |

## 二、周度报告（`YYYY-WXX.md`）格式规范

### 2.1 文件头

```markdown
# 📊 周度回顾分析 — {年}年第{周号}周 ({起始日期} ~ {结束日期})

> 生成时间: {生成日期} | 数据完整性: screening_raw {状态} screening_predictions {状态} manual_predictions {状态} screening_analysis {状态}
> T+1 行情覆盖: {已验证日期范围} ({已验证只数})，{待验证日期} ({待验证只数})
```

### 2.2 章节结构（固定六章）

| 章节 | 标题 | 必选 | 核心内容 |
|------|------|------|----------|
| 一 | 本周市场环境概览 | ✅ | 每日市场均涨幅、普跌日标记、选股数、特征 |
| 二 | 自动选股评分系统表现 | ✅ | 整体数据 + 分层分析 + 砖形图持砖分析 |
| 三 | 手动补充选股回顾 | ✅ | 手动选股概览 + 有数据日的 T+1 验证 |
| 四 | 失败案例深度分析（Top 5） | ✅ | 预测偏多但跌幅最大的 5 只 |
| 五 | 成功案例提炼（Top 5） | ✅ | T+1 涨幅最大的 5 只 |
| 六 | 本周可优化点 & 迭代方向 | ✅ | P0/P1/P2 分级，标注实施状态 |

### 2.3 各章节详细规范

#### 第一章：本周市场环境概览

**必含表格1 — 每日市场概览**：

| 列 | 说明 | 数据来源 |
|----|------|----------|
| 交易日 | 格式 `MM-DD (周X)` | 日历 |
| 市场均涨幅 | 当日选股池所有股票的平均涨跌幅 | screening_raw |
| 普跌日 | 均涨幅 < -1% 标记为"🔴 是" | 计算 |
| 选股数 | 当日扫描出的股票数量 | screening_raw |
| 特征 | 一句话描述市场状态 | 人工总结 |

> ⚠️ **数据缺失兜底规则**：当 `screening_raw/{date}.json` 缺少 `market_avg`、`is_bearish_day` 等关键字段时（如06-10仅含date和results两个key），**严禁标注为"待确认"**，必须按以下优先级补充：
> 1. 从 `screening_analysis/{date}.md` 中提取市场均涨幅和普跌日判定
> 2. 从 `db/market.db` 的 `index_daily` / `stock_daily` 表计算全市场均涨
> 3. 如以上均无数据，标注为"⚠️ 数据缺失"并说明原因，但不留"待确认"空位
>
> **案例**：W24的06-10 screening_raw缺少market_avg字段，初始报告标为"待确认"，后从screening_analysis.md确认市场均涨-1.0%是普跌日，导致普跌日从2天误判为3天→已修正。

**必含表格2 — OAMV 活跃市值走势**：

| 列 | 说明 | 数据来源 |
|----|------|----------|
| 日期 | 格式 `MM-DD` | 日历 |
| OAMV收盘 | 当日活跃市值收盘值 | oamv_daily 表 |
| 日变化 | (今日OAMV - 昨日OAMV) / 昨日OAMV × 100% | 计算 |
| 说明 | 一句话描述资金流向特征 | 结合 screening_analysis |

> ⚠️ **OAMV 不可遗漏**：每周市场环境概览**必须包含 OAMV 活跃市值走势表和分析段落**。数据来源为 `db/market.db` 的 `oamv_daily` 表（字段：date, open, close, high, low），也可从 `screening_analysis/{date}.md` 的"OAMV 活跃市值"章节提取。OAMV 是判断市场资金面偏多/偏空的核心指标，缺失会导致市场分析片面。
>
> **案例**：W24初始报告遗漏OAMV分析，后补充发现OAMV连续2日大幅流出(-2.05%、-1.07%)，与方向准确率仅44%吻合——OAMV分析对理解"为何本周预测表现差"至关重要。

**必含分析段落**：OAMV本周整体走势特征（流入/流出、与市场均涨幅的关联、对选股表现的解释）。

**必含总结**：概括本周整体市场格局（3-5 个要点），**必须包含OAMV资金面判断**。

#### 第二章：自动选股评分系统表现

**2.1 整体数据表**（固定指标）：

| 指标 | 计算方式 |
|------|----------|
| 本周总选股 | 5天合计只数 |
| 已验证 | 有 T+1 收盘数据的只数 |
| 平均 T+1 涨跌 | 已验证股票的 T+1 涨跌幅均值 |
| T+1 上涨比例 | T+1 涨幅 > 0 的比例 |
| 开盘方向准确率 | 预测方向与 T+1 开盘方向一致的比例 |
| 收盘方向准确率 | 预测方向与 T+1 收盘方向一致的比例 |

**2.2 按评分等级分层表**（S/A/B/C 四级）。

**2.3 砖形图持砖分析**（本章核心）：

必含分析维度：
1. **T+1 红砖保持率**（整体 + 按等级）— 核心胜率指标
2. **T+1 红/绿砖对收益的区分度** — 红砖组 vs 绿砖组平均收益
3. **按定式 T+1 红砖率** — 各定式的红砖保持能力对比
4. **持砖天数分布** — 0/1/2/3 天的分布
5. **评分等级对 T+1 红砖率的区分度** — 验证评分是否能预测红砖
6. **典型案例对比** — 高分翻绿 vs 低分持红的案例

> **红/绿砖计算规则**：`当日砖值 - 前日砖值 > 0` 为红砖，`< 0` 为绿砖。
> 严禁使用"砖值 > 0"作为红砖判定条件。

#### 第三章：手动补充选股回顾

- 按日期列出手动选股数量和方向分布
- 对有 T+1 数据的日期进行验证（表格形式）
- 标注严重误判案例

#### 第四章：失败案例深度分析

**选取规则**：从已验证数据中，按 T+1 跌幅从大到小排序，取 Top 5。

**每个案例固定格式**：

| 项目 | 详情 |
|------|------|
| 日期 | {选股日期} |
| 评分 | {分数} ({等级}) |
| 定式 | {触发的定式} |
| 预测 | {预测方向} |
| 风险扣分 | {触发的风险项和分值} |
| 分析 | {失败原因分析} |

**必含"共性总结"**：提炼失败案例的共同特征。

#### 第五章：成功案例提炼

**选取规则**：从已验证数据中，按 T+1 涨幅从大到小排序，取 Top 5。

**每个案例固定格式**：

| 项目 | 详情 |
|------|------|
| 日期 | {选股日期} |
| 评分 | {分数} ({等级}) |
| 定式 | {触发的定式} |
| 风险扣分 | {触发的风险项和分值} |
| 亮点 | {成功原因分析，如被误扣了什么} |

**必含"共性总结"**：提炼成功案例的共同特征。

#### 第六章：本周可优化点 & 迭代方向

**结构**：
1. **评分系统可优化点** — 按优先级 P0/P1/P2 排列
2. **预测分析可优化点** — 数据格式、流程等
3. **下周关注重点** — 3-5 个具体验证目标

**优化项格式**：
```markdown
#### {状态emoji} {优先级}：{标题} — {实施状态}

- **问题**：{数据支撑的问题描述}
- **已实施**：{如已实施，写明具体变更}（或 **建议方向**：{如未实施}）
- **待观察**：{下周需要验证的预期}
```

状态 emoji 规则：
- 🔴 = 未实施的 P0
- 🟡 = 未实施的 P1/P2
- ✅ = 已实施

## 三、持续迭代日志（`EVOLUTION.md`）格式规范

### 3.1 文件头

```markdown
# 📈 选股系统持续迭代日志

> 每周更新，记录优化方向、对过往方向的反思和总结
> 最新的周在最上面
```

### 3.2 每周条目结构（固定四节）

```markdown
## {年}-W{周号} ({起始日期} ~ {结束日期})

### 本周数据快照
### 发现的问题
### 提出的优化方向
### 对过往优化方向的反思
```

#### 本周数据快照

固定表格，所有指标必须包含：

| 指标 | 说明 |
|------|------|
| 预测总数 | 自动选股总只数 |
| 有T+1数据 | 已验证只数 |
| 平均T+1涨跌 | 均值 |
| 上涨比例 | >0 的比例 |
| 开盘准确率 | 方向一致率 |
| 收盘准确率 | 方向一致率 |
| S/A级平均T+1 | 分别列出 |
| B/C级平均T+1 | 分别列出 |
| T+1红砖保持率 | 核心指标 |
| T+1翻绿率 | = 1 - 红砖保持率 |

#### 发现的问题

- 按严重程度排序：🔴 高 > 🟡 中 > 🟢 低
- 每条必须包含：问题描述 + 数据佐证 + 严重程度
- 编号连续

#### 提出的优化方向

固定格式：
```
{序号}. **[OPT-W{周号}-{序号}] {标题}** — {一句话描述} | 优先级：**{高/中/低}** | 状态：{状态}
```

状态枚举值：
- `待设计` — 方向明确但需要设计具体方案
- `待验证` — 需要更多数据才能确认是否实施
- `✅ 已实施 ({日期})` — 已完成代码变更
- `✅ 部分实施 ({日期}，{说明})` — 部分完成
- `❌ 已否决 ({日期}，{原因})` — 经验证后放弃

#### 对过往优化方向的反思

- 回顾之前各周提出的 OPT 项
- 验证已实施项的效果（用本周数据）
- 标注仍需继续观察的项
- 首周写 `> 首周，无历史优化方向可回顾。`

## 四、数据处理规则

### 4.1 数据完整性校验（生成前必做）

1. 确认当周 5 个交易日的 `screening_raw` 文件是否齐全
2. 确认 `screening_predictions` 文件是否齐全
3. 确认 T+1 行情数据覆盖范围（周五的预测通常无 T+1 数据）
4. 在报告头部标注校验结果

### 4.2 T+1 涨跌幅计算

```
T+1 涨跌幅 = (T+1收盘价 - T日收盘价) / T日收盘价 × 100%
```

- T 日 = 选股日（screening_raw 的日期）
- T+1 = 选股日的下一个交易日
- 收盘价来源：screening_raw 中的 `close` 字段

### 4.3 红/绿砖判定

```
砖色(T) = "红砖" if 砖值(T) - 砖值(T-1) > 0 else "绿砖"
```

- 砖值来源：screening_raw 中的 `brick_value` 或等效字段
- **严禁**使用 `砖值 > 0` 作为红砖判定
- 如缺少前日砖值数据，该条记录标记为"无法判定"

### 4.4 方向准确率计算

- 预测方向字段：统一使用 `pred_direction`
- 方向映射：偏多/震荡偏多/强烈偏多 → 多；偏空/中性偏空 → 空；中性/观察 → 不计入
- 开盘准确：预测"多" + T+1 开盘涨 / 预测"空" + T+1 开盘跌
- 收盘准确：预测"多" + T+1 收盘涨 / 预测"空" + T+1 收盘跌

### 4.5 市场均涨幅 & 普跌日

```
市场均涨幅 = 当日选股池所有股票的 T+1 涨跌幅均值
普跌日 = 市场均涨幅 < -1%
```

## 五、生成工作流程

### 5.1 前置条件

1. 当周 5 个交易日已过（通常周六/周日生成）
2. 至少有 4 天的 T+1 行情数据（周五的通常需等下周一补充）

### 5.2 生成步骤

1. **数据校验** — 检查 4 个数据源目录的文件完整性
2. **读取数据** — 逐日读取 screening_raw 和 screening_predictions
3. **计算指标** — 按本文档第四章的规则计算所有指标
4. **生成周报** — 按第二章的固定六章结构生成 `YYYY-WXX.md`
5. **更新迭代日志** — 在 `EVOLUTION.md` 顶部追加本周条目
6. **交叉验证** — 确保周报和迭代日志中相同数据一致

### 5.3 生成方式

通过 Copilot 对话生成，无中间脚本。生成时应一次性读取所有数据后统一计算，避免逐日零散分析导致数据不一致。

## 六、跨周一致性保证

### 6.1 指标口径固定

- 所有指标的计算公式在本文档第四章定义，不允许临时变更
- 如需调整口径，必须先更新本文档，再重新生成

### 6.2 格式对齐

- 周报的六章结构不可增减（可在章节内增加子节）
- EVOLUTION.md 的四节结构不可增减
- 表格列名和顺序保持一致

### 6.3 术语统一

| 术语 | 含义 | 严禁混用 |
|------|------|----------|
| T+1 红砖保持率 | 选股次日仍为红砖的比例 | ≠ "上涨率" |
| 红砖 | 当日砖值 - 前日砖值 > 0 | ≠ "砖值 > 0" |
| 绿砖 | 当日砖值 - 前日砖值 < 0 | ≠ "砖值 < 0" |
| 普跌日 | 市场均涨幅 < -1% | ≠ "跌幅较大的日子" |
| 定式 | N型起跳/横盘起跳/上升波段延续 | 三选一，不可自创 |
| pred_direction | 预测方向字段名 | 不可用其他字段名 |

### 6.4 历史数据不可修改

- 已生成的周报原则上不再修改数据部分
- 仅允许追加"实施状态"标注（如优化方向从"待实施"变为"已实施"）
- 如发现历史数据计算错误，在当周报告中注明勘误
