## 一、目标

把 `代码.txt` 公式里的两块能力，接到现有「每日选股 → 次日预测」链路上：

1. **模拟收益**：按战法买入后，到底赚了多少（次日 / 脱成本看 5 日高点的收益结算）。
2. **统计战绩**：胜率、平均收益、复利、最大回撤、连续做错次数。

注意：买点逻辑（黄线绿转红 + 强红砖）已成熟，**本次不动买点**，只补「买入之后」的收益与战绩评估。

## 二、现有链路现状（已摸清）

### 2.1 全链路数据流

```
screen_full.py（全市场扫描，每日）
   └─→ output/screening_raw/{date}.json     （Top50 命中股 + 评分拆解 + 指标）
         └─→ Agent 加工
               └─→ output/screening_predictions/{T}.json   （每股带 expected_direction 等预测）
                     └─→ backfill_predictions.py（T+1 后回填）
                           └─→ 回填字段：open_chg / day_chg / open_correct / close_correct / sector_reverted
                                 └─→ prediction_accuracy.py（统计方向准确率）
```

另有一条**分钟级**支线（盘中路径裁定）：
`review_intraday.py` → `intraday_review` 表 → `intraday_accuracy.py`（真实准确率/蒙对归因）。

### ⚠️ 重要：项目里已存在「收益回填」基础设施（之前调研遗漏，现已补全）

除了上面 `predictions` 这条「方向准确率」链路，项目里**还有一条独立的「真实收益回填」链路**，与本次「模拟收益」目标高度重合，必须复用而非另起炉灶：

```
core/scoring/outcomes.py（OutcomesFiller）
   每日调 fill_for_today(today)：扫 today-1/-2/-3 的 scoring_picks
   └─→ 计算 T+1/T+2/T+3 当日涨跌 + 是否绿砖
         └─→ scoring.db 的 outcomes 表（t1_return/t2_return/t3_return + t1/t2/t3_is_green）
```

- **交易日历**：`OutcomesFiller` 用 `000001`（平安银行）日线序列作为交易日历（主板长期不停牌），解决了「连续取 N 个交易日」的问题——**这正是本次「5 日高点收益」需要连续取 T+1..T+5 的现成工具**，无需自己写取日历逻辑。
- **收益语义**：`_compute_window` 现在是「**当日涨跌**」语义（fill_idx 收盘 vs fill_idx-1 收盘），不是「score_date 到 fill_date 累计」。
- **样本来源**：`outcomes` 链路读 `output/scoring_picks/{date}.json`（评分系统的票），而 `predictions` 链路读 `output/screening_predictions/{T}.json`（砖形图选股的票）——**两套样本来源不同**，挂载点需明确选一套（见 4.5）。
- **现成数据库表 `outcomes`**：字段 `score_date / symbol / t1_return / t1_is_green / t2_return / t2_is_green / t3_return / t3_is_green`，已有 `save_outcomes` / `load_outcomes`。本次若需落库，**优先扩展此表**（如加 `t5_high_return / sim_return` 列），而非新建表。

### 2.2 关键文件清单

| 文件 | 职责 | 与本次的关系 |
|------|------|------|
| `scripts/screen_full.py` | 全市场选股，写 `screening_raw/{date}.json` | 数据源头，含 `close/open/high/low/prev_close/brick_val` 等 |
| `output/screening_predictions/{T}.json` | 砖形图选股每股预测，含 `expected_direction` | 方向准确率链路样本来源 |

### 2.3 现状结论

- 现有体系有**两套口径**：
  - 「**方向猜没猜对**」（`predictions` 链路的 open_correct / close_correct）——只判涨跌方向。
  - 「**真实当日收益**」（`outcomes` 链路的 t1/t2/t3_return）——已有 T+1/T+2/T+3 收益，但**没有「脱成本看 5 日高点」的结算逻辑，也没有复利/回撤/连错战绩聚合**。
- 因此 `代码.txt` 第 2、3 段里真正的**增量**是：① 「脱成本 → 看 5 日高点」的收益结算口径；② 复利 / 最大回撤 / 连续做错次数这套**战绩聚合**。这两块现有体系都没有。
- 取连续 N 个交易日的能力（算 5 日高点必需）**已由 `OutcomesFiller` 的 `000001` 交易日历提供**，不存在之前担心的「需要自己写取日历」问题；真正的约束是「**T+5 行情要等到 5 个交易日后才齐**」（见 4.1）。

## 三、公式 → 项目的逐项映射

把 `代码.txt` 第 2、3 段翻译成项目里可落地的计算口径：

### 3.1 模拟收益（逐股，回填时算）

> ⚠️ 口径修正：逐字拆 `五日涨幅:=MAX(HHV(REFX(C,5),5)/C-1,-100)`。
> `REFX(C,5)` 是把收盘序列**前移 5 位**（取未来值），`HHV(...,5)` 再取其 5 日最高，
> 展开后等于 **T+1..T+5 这 5 个交易日「收盘价」的最高值** ÷ T 日收盘 − 1。
> **注意：用的是 `close`（收盘价），不是 `high`（最高价）**——这点之前写错了。
> 外层 `MAX(..., -100)` 是防止极端缺失值，对正常数据无影响。

| 公式变量 | 含义 | 项目实现口径（已核对） |
|----------|------|--------------|
| `次日涨幅:=IF(CURRBARSCOUNT=1,C,REFX(C,1))/C-1` | 买入次日收盘涨跌幅 | T+1 收盘 ÷ T 收盘 − 1；等价于 `outcomes` 的 `t1_return` |
| `五日涨幅` | **T+1..T+5 五日「收盘价」最高值** ÷ T 收盘 − 1 | 取 T+1..T+5 五个交易日的 `close` 最大值 / T 收盘 − 1（**非 high**） |
| `脱成本 := 次日涨幅>=5%` | 次日收盘涨 ≥5% 视为脱离成本 | `t1_return >= 0.05` |
| `总涨幅 := IF(脱成本, 五日涨幅, 次日涨幅)` | 最终收益结算 | 同逻辑，输出 `sim_return`（单笔模拟收益） |

> 建议给每股新增回填字段：`sim_next_ret`（次日收益）、`sim_5d_high_ret`（5日收盘最高收益）、`sim_escaped_cost`（是否脱成本 bool）、`sim_return`（最终结算收益）。其中 `sim_next_ret` 可直接复用 `outcomes.t1_return`。

### 3.2 战绩统计（逐日/累计聚合）

> 说明：公式里 `总涨幅` 是「比例」（如 0.03 表示 3%）。项目内部统一用比例存储，展示时 ×100。
> 以下口径均逐字核对了公式语义。

| 公式变量 | 公式精确语义 | 项目聚合口径 |
|----------|------|----------|
| `买入次数:=SUM(买入,0)` | 从第一根 K 线起买入信号累计次数 | 参与统计的样本数（有有效 `sim_return` 的股票数） |
| `胜次:=SUM(IF(买入 AND 总涨幅>0.02,1,0),0)` | 收益 >2% 才算赢 | `sim_return > 0.02` 的计数（**阈值是 2%，不是 0**） |
| `胜率:=胜次/MAX(买入次数,1)` | 胜次 / 买入次数 | 同 |
| `均值` | `SUM(有效总涨幅)/买入次数`（剔除 −100 缺失值） | `mean(有效 sim_return)`，展示 ×100 |
| `复利:=MULAR(IF(买入,1+总涨幅,1),0)` | 每个买入信号的 `(1+总涨幅)` **连乘** | `prod(1 + sim_return) − 1`（仅对有效样本），展示 ×100 |
| `最大回撤:LLV(总涨幅,0)` | 自首个信号起 `总涨幅` 序列的**最小值** | `min(sim_return)`——即**最差单笔收益**，并非账户资金曲线回撤（口径取舍见 4.3） |
| `连续做错次数` | 见下方专门说明 | 自上一次「做对(总涨幅>0)」以来累计做错次数的历史最大值 |
| `总天数:=BARSCOUNT(买入)` | 从**首个买入信号**那根 K 线到当前的总 K 线数 | 跨度天数，**不等于买入次数**（之前混淆，已更正） |

**`连续做错次数` 逐字拆解**（`HHV(COUNT(买入 AND 0>总涨幅, BARSLAST(买入 AND 总涨幅>0)),0)`）：
- `BARSLAST(买入 AND 总涨幅>0)`：距「上一次做对的买入」过去了几根 K 线。
- `COUNT(买入 AND 0>总涨幅, 上述周期)`：在「上次做对」至今这段窗口内，做错(收益<0)的买入次数。
- 最外层 `HHV(...,0)`：取该值的历史最大 → **「两次盈利之间最多连续做错几次」**。
- 项目实现：把样本按时间排序，遍历，遇到 `sim_return>0` 清零计数、否则 +1，全程记录最大值。

> 聚合可做两层：**按日**（当天选股战绩）+ **累计**（历史全部，体现复利曲线）。还可按 `grade`（A/B）、`pattern`（N型/横盘/延续）、`group`（涨停/强势/普通）分组，看哪类票适配买入战法——呼应公式开头「萝卜青菜各有所爱」。
> ⚠️ 但「连续做错次数」依赖**明确的时间先后顺序**：公式里是单只股票的 K 线时序；项目里若把多只股票混在一天里，需先定义排序口径（建议按 `score_date` 升序，同日内按评分降序），否则该指标无意义。

## 四、关键风险与待决策点（需你拍板）

### 4.1 ⏰ 5 日高点收益的「数据延迟」问题（最重要）

- 公式用了未来函数 `REFX(C,5)`，在通达信里是「上帝视角」无所谓。
- 但在项目里，T 日选股后，**要等到 T+5 才有完整 5 日行情**才能算 `sim_5d_high_ret`。
- **决策点**：
  - 方案 A：回填分两阶段——T+1 先回填 `sim_next_ret`，T+5 再补 `sim_5d_high_ret` 和最终 `sim_return`。
  - 方案 B：简化口径，只用「次日收益」做战绩（去掉 5 日高点），实现最简单，但丢了「脱成本持有」的逻辑。
  - 方案 C：可配置持有天数（如 T+1 / T+3 / T+5 三套并存对比）。

### 4.2 「买点」口径差异

- 公式的 `买入` 信号 = 黄线绿转红 + 强红砖；而项目预测里的票是**评分选出来的 Top50**，买点口径不完全等价。
- **决策点**：模拟收益的「买入样本」用哪个？
  - 用现有预测 stocks[] 全体（评分口径）—— 改动最小，直接复用。
  - 还是严格按公式买点重算 —— 需要额外接砖形图买点指标，工作量大。

### 4.3 「最大回撤」口径

- 公式的 `最大回撤 = LLV(总涨幅)` 实际是「**单笔最差收益**」，不是账户资金曲线回撤。
- **决策点**：是沿用公式口径（最差单笔），还是做成真正的「复利资金曲线最大回撤」（更专业）。

### 4.4 落库 vs 只写 JSON

- 现有方向准确率是直接回写 `predictions/{T}.json`，不落库；`outcomes` 收益则落 scoring.db 的 `outcomes` 表。
- **决策点**：战绩存哪？
  - 跟着 `predictions/{T}.json` 回写（轻量、与方向准确率一致，但跨日累计要遍历所有 json）。
  - **扩展现成 `outcomes` 表**（加 `sim_5d_high_return / sim_escaped_cost / sim_return` 列），跨日累计/复利曲线一条 SQL 搞定——**推荐**。

### 4.5 ⭐ 样本来源用哪一套（新增，关键决策）

项目里有两套候选样本，挂载点不同、改动量不同：

| 样本来源 | 文件 | 票的口径 | 复用基础设施 |
|----------|------|----------|--------------|
| **A. 砖形图选股预测** | `output/screening_predictions/{T}.json` | 砖形图定式 Top50 + Agent 预测 | `backfill_predictions.py` |
| **B. 评分系统选股** | `output/scoring_picks/{date}.json` | 主板评分票 | `outcomes.py` 的 `OutcomesFiller`（**已有 T+1/T+2/T+3 收益**） |

- 若目标是「评估砖形图买入战法」→ 选 **A**（与 `代码.txt` 战法同源），但要自己接 5 日收益回填。
- 若想**最小改动**直接复用 `OutcomesFiller` 的交易日历 + 三窗口收益 → 选 **B**，只需补「5 日高点 + 脱成本结算 + 战绩聚合」。
- **决策点**：选 A 还是 B？还是两套都加？（建议先确认你日常实际看的是哪套选股结果）

## 五、推荐实现方案（待评审）

> 倾向「**最小侵入 + 复用现成 `outcomes` / 交易日历基础设施**」。
> 下面给出两套方案对应 4.5 的样本来源 A / B，最终选哪套待你确认。

### 方案 B（推荐，复用度最高 —— 接评分系统 `outcomes` 链路）

1. **收益结算纯函数**（新建 `core/scoring/battle_stats.py`）：
   - `compute_5d_high_return(closes_t1_to_t5, t_close)` → 5 日收盘最高收益（用 **close**）。
   - `settle_return(t1_return, high_5d_return, escape_threshold=0.05)` → 实现「脱成本则取 5 日高点，否则取次日」，返回 `sim_return`。
2. **5 日高点回填**：在 `OutcomesFiller` 里加一个窗口（复用其 `000001` 交易日历连续取 T+1..T+5 的 close），
   把 `sim_5d_high_return / sim_escaped_cost / sim_return` 写入扩展后的 `outcomes` 表。
   - 5 日未齐时只写 `t1_return`、标记待补，第 5 个交易日后由每日任务自然补齐（`OutcomesFiller` 本就是增量回填模型）。
3. **战绩聚合纯函数**（`battle_stats.py`）：`aggregate_battle_stats(records)` →
   买入次数 / 胜率(>2%) / 均值 / 复利(连乘) / 最大回撤(最差单笔) / 连续做错次数（按 score_date 时序）。
4. **战绩报告脚本**（新建 `scripts/battle_stats.py`）：读 `outcomes` 表，
   打印按日 + 累计 + 分组（grade/pattern/group）战绩，格式参照 `prediction_accuracy.py`。
5. **建表扩展**：在 `core/data/database.py` 的 `outcomes` 表加列
   `sim_5d_high_return REAL / sim_escaped_cost INTEGER / sim_return REAL`，同步改 `save_outcomes` / `load_outcomes`。

**方案 B 改动文件**：`core/data/database.py`（加 3 列 + 读写）、`core/scoring/outcomes.py`（加 5 日窗口）、新建 `core/scoring/battle_stats.py`（结算+聚合纯函数）、新建 `scripts/battle_stats.py`（报告）。

### 方案 A（接砖形图选股预测 `predictions` 链路）

1. 结算/聚合纯函数同方案 B（放 `battle_stats.py`，与样本来源解耦）。
2. **回填挂载**：在 `backfill_predictions.py` 的 `backfill_one()` 里，
   除现有方向回填外，连续取 T+1..T+5 的 close（需自己写取连续交易日，或复用 `OutcomesFiller._get_calendar`），
   调结算函数写入 `predictions/{T}.json` 的 stocks[]（`sim_*` 字段），5 日未齐标 `sim_pending=True`。
3. 战绩报告在 `prediction_accuracy.py` 增打印块或新建脚本。

**方案 A 改动文件**：新建 `battle_stats.py`、`backfill_predictions.py`（回填循环）、`prediction_accuracy.py`（报告块）。

> 两套都**不动买点、不动选股引擎**，结算/聚合纯函数完全共用，仅样本来源与挂载点不同。
